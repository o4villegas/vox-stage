## 8. Workers Builds failure — root cause (verified) and remediation plan (for approval)

**Symptom.** Every push triggers the `voxstage-staging` Workers Builds project (created by
Lando 20:50 UTC). Builds end in
`✘ [ERROR] Missing entry-point to Worker script or to assets directory` after
`Executing user deploy command: npx wrangler versions upload` (wrangler 4.128.0, builder
log pasted by Lando, builds `0fa40aa8` and `a32406c2`).

**Root cause — measured, 2026-09-01 21:1x UTC, this sandbox.**
- Running the builder's exact command non-interactively against the real repo
  (`CI=1 npx wrangler@4.128.0 versions upload --dry-run` at repo root) reproduces the
  identical error, exit 1. The repo has no `wrangler.jsonc`, no Worker entry-point and no
  assets directory — nothing for wrangler to upload. It is not a Cloudflare misconfiguration
  and not a token/permission problem (the builder never got as far as authentication).
- The same command against a scratch skeleton laid out per `docs/M1-PLAN.md` §2
  (`wrangler.jsonc` at root with `main: worker/src/index.ts` and
  `assets.directory: ./app/dist`; a 12-line fetch handler that serves `/api/*` as JSON and
  everything else from assets; one `index.html`) **succeeds**: `Total Upload: 0.36 KiB`,
  binding `env.ASSETS`, `--dry-run: exiting now`, exit 0. The scratch folder is outside the
  repo; the repo is untouched (rule 1).
- Side observation: interactive `wrangler deploy` in the repo auto-detects
  "Framework: Static, Output Directory: spikes" and offers to write a config for it. That
  would publish the spike folder as the Worker — never accept that prompt.
